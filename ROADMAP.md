# Дорожная карта и порядок

Живой список идей и доработок калькулятора полураспада. Его ведёт ветка-куратор проекта
(«Вести идеи и порядок в калькуляторе»). Любая новая идея сначала попадает сюда, в раздел
[«Входящие»](#входящие), а куратор раскладывает её: в очередь, отложить или отклонить, всегда с причиной.

Последний аудит: 27.11.2026, состояние `main` после слияния PR #9 (все ночные функции).

## Главное правило

Калькулятор делается для человека, который видит его впервые. Основной путь — четыре шага:
**изотоп → сколько было → сколько времени → результат**. Всё, что не нужно на этом пути, не должно ему мешать.

## Правила для каждой доработки

1. **Одно место.** У функции одно место на экране, где её ищут, плюс пункт в меню (меню — полный каталог команд).
   Третьего входа не делаем.
2. **Шаги 1–4 — только основной путь.** Инструменты для специалистов живут в меню и в свёрнутых блоках
   «Дополнительно», а не кнопками внутри шагов.
3. **Встраивать, а не добавлять.** Если можно обойтись без новой кнопки (вставка из буфера, распознавание формата
   при открытии файла), так и делаем.
4. **Одни слова везде.** Название кнопки одинаково в интерфейсе, справке (`help.js`), `README.md` и меню Windows.
   См. [«Словарь»](#словарь).
5. **Веб, Windows и Android одинаковы.** Меню `desktop/main.js` повторяет веб-меню.
6. **Новая функция = модуль + тест + справка.** Логика — в отдельном `web/<имя>.js`, `app.js` только связывает.
   Подключить везде: `index.html` (script), `sw.js` (`FILES` и версия `CACHE`), `artifact/build_artifact.py` (`FILES`),
   `tests/run_all.js`, `help.js`, `README.md`.
7. **Один PR — одна понятная пользователю вещь.** В описании: что видит пользователь, где это найти, скриншот,
   какие тесты прошли.

## Аудит 27.11: перегруз и беспорядок

1. **Меню «Данные» — 10 пунктов двух разных видов**: справочник (ядерные данные, таблица Менделеева, правки T½,
   обновление IAEA) и расчётные инструменты (подбор, генератор, пересчёт, погрешность, масса, схема).
2. **Кнопки специалистов внутри шагов для новичка.** «Схема распада» стоит в ряду выбранных изотопов и выглядит как
   ещё один изотоп. «Пересчитать от измерения» — в шапке таблицы шага 2, рядом с единицами.
3. **Разные названия.** В шапке «Калькулятор распада», в заголовке окна и справке «Калькулятор полураспада»,
   на телефоне «Полураспад». В README «галочка «Число атомов»» (в интерфейсе «Атомы и масса») и
   «нажмите «Расчёт»» (кнопка называется «Рассчитать»).
4. **Меню Windows не совпадает с веб-меню.** В Windows есть «Правка», «Расчёт», «Примеры», «Вид», а в «Виде» —
   «Инструменты разработчика», которые обычному пользователю не нужны.
5. **Несколько «текущих версий».** Опубликованная веб-страница на claude.ai — версия до ночных функций;
   «Предпросмотр новых функций» — отдельная страница; копия кода в папке проекта (`/mnt/project-files/halflife-app`)
   отстала от `main` (нет `masses.js`, `amount.js`, `scheme.js`, `elements.js`); сборки `dist/` от 03:05,
   без ночных функций.
6. **SPEC.md описывает первую ночь**: «строгий инженерный стиль», меню «Примеры», 7 скриптов, владельцы файлов трёх
   старых веток. Новый агент, прочитав его, может пойти не туда.
7. **10 слитых веток `feature/*`** остались в репозитории.
8. **`app.js` — 2918 строк.** Ночные функции (генератор, масса, пересчёт, погрешность, подбор, схема, обновление IAEA)
   дописаны прямо в него, это около 800 строк. Пока работает, но каждая новая функция повышает риск конфликтов.

## Идеи

### Принято, ждёт очереди

- **Вставка столбца активностей из Excel.** Ctrl+V в первую ячейку «Было вначале» заполняет весь столбец.
  Заказчик говорил про цепочки до ~32 изотопов, вводить по одному долго. Новой кнопки не нужно.
  Разбор таблицы уже есть в `formula-import.js` (CSV и TSV из PR #12) — использовать его, а не писать второй.
- **Проверка на настоящих Windows и Android.** Нужен пользователь или его компьютер.

### Отложено

- **Ссылка, открывающая готовый расчёт** (параметры в адресе) — когда появится постоянный адрес.
- **Подпись программы для Windows сертификатом** (убирает окно «Windows защитила компьютер») — платно.
- **Английский интерфейс** — запроса нет.

### Отклонено

- **Отдельные пункты меню на каждый формат импорта и экспорта формул.** Дублирует вкладку «Формулы»;
  вход один — «Файл → Открыть…».
- **Переключатель «простой / инженерный режим» внутри `main`.** Два интерфейса вдвое увеличивают проверку и путают;
  инженерный вид хранится в ветке `classic`, инструменты — в меню.
- **Аккаунты и облачное хранение.** Программа офлайн, расчёты заказчика не должны уходить в сеть.

### Входящие

Сюда записываются новые идеи до разбора. Сейчас пусто.

## Ветки и PR

- `main` — только через PR и после тестов: `LANG=C.UTF-8 node tests/run_all.js`.
- `classic` — архив прежнего «инженерного» вида, не развивается.
- Имена веток: `feature/<что>` — новая функция, `fix/<что>` — исправление, `docs/<что>` — тексты;
  `claude/*` — служебные ветки сессий.
- Слитая ветка удаляется.
- Перед слиянием — ревью куратора по чек-листу.

### Чек-лист ревью

- [ ] Не дублирует существующую функцию? Где её «одно место»?
- [ ] Шаги 1–4 не стали длиннее или сложнее для новичка?
- [ ] Названия совпадают в интерфейсе, `help.js`, `README.md`, меню Windows?
- [ ] Подключено везде: `index.html`, `sw.js` (`FILES` и `CACHE`), `artifact/build_artifact.py`, `tests/run_all.js`?
- [ ] Есть тест, `run_all.js` проходит? Если менялся `desktop/`, прогнан `e2e-electron.js` на собранной программе?
- [ ] Проверено скриншотом на телефоне (360 px) и в тёмной теме?
